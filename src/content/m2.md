## מה זה בכלל "לתכנת"?

תוכנית מחשב היא **רשימת הוראות** שהמחשב מבצע אחת אחרי השנייה. **JavaScript** היא השפה שרצה בכל דפדפן בעולם, וגם בשרתים (עם Node.js, שנלמד במודול 3). כמעט כל מה שתבנה כמפתח Full Stack ייכתב בה – או בגרסה המשופרת שלה, **TypeScript**.

### אנלוגיה: מתכון במטבח

- **Variable** (משתנה) = **קופסה עם מדבקה**. על המדבקה כתוב "סוכר", ובתוכה 200 גרם. אפשר להסתכל בקופסה, ולפעמים להחליף את התוכן.
- **Type** (סוג) = **מה מותר לשים בקופסה**: טקסט, מספר, כן/לא.
- **Function** (פונקציה) = **מתכון קטן שאפשר להשתמש בו שוב ושוב**: "להכין רוטב" – נותנים לו מצרכים (**Parameters**) ומקבלים תוצאה (**Return value**).
- **Condition** (תנאי) = "**אם** הבצק דביק – **אז** תוסיף קמח, **אחרת** תמשיך".
- **Loop** (לולאה) = "תערבב 10 פעמים" או "לכל ביצה בקרטון – תשבור אותה".

עם חמשת הכלים האלה בלבד אפשר לכתוב כמעט כל לוגיקה: לחשב מחיר עם הנחה, לבדוק אם סיסמה חזקה, לסנן הודעות בצ׳אט.

> [!tip] אל תנסה לשנן הכל. הדרך הכי טובה ללמוד היא לפתוח את ה-**Console** בדפדפן (F12) ולהקליד את הדוגמאות בעצמך. טעויות הן חלק מהלמידה – השגיאה האדומה היא המורה הכי טוב שלך.

### למה זה חשוב לך?

React, Node.js, מסדי נתונים, AI – הכל נבנה מעל אותם יסודות. מפתח Senior לא יודע "יותר פקודות"; הוא פשוט שולט ביסודות האלה כל כך טוב שהוא כותב קוד ברור, צפוי ובלי הפתעות.

## 1. Variables – משתנים עם `const` ו-`let`

```typescript שני סוגי משתנים
const userName = 'אורי';   // const – אי אפשר להציב ערך חדש
let cartCount = 0;          // let – אפשר לשנות בהמשך
cartCount = cartCount + 1;  // עכשיו 1
```

**כלל הזהב:** תמיד מתחילים עם `const`. עוברים ל-`let` רק כשבאמת צריך לשנות את הערך. את `var` (הדרך הישנה) **לא משתמשים יותר** – יש לו התנהגויות מבלבלות.

## 2. Primitive Types – סוגי הערכים הבסיסיים

| Type | מה זה | דוגמה |
|---|---|---|
| `string` | טקסט | `'שלום'`, `"abc"` |
| `number` | מספר (שלם או עשרוני) | `42`, `19.9` |
| `boolean` | כן / לא | `true`, `false` |
| `null` | "ריק בכוונה" – אין ערך, והחלטנו על זה | `null` |

> [!note] ההבדל בין `null` ל-`undefined` מבלבל את כולם. כלל פשוט: `undefined` = "שכחו / עוד לא הגיע", `null` = "בדקנו, ואין כלום". למשל: `user.middleName = null` – אין לו שם אמצעי.

## 4. Functions – פונקציות

```typescript שלוש דרכים לכתוב פונקציה
// Function declaration – הדרך הקלאסית
function add(a, b) {
  return a + b;
}

// Arrow function – הדרך המודרנית (נפוצה מאוד ב-React)
const multiply = (a, b) => {
  return a * b;
};

// Arrow function קצרה – כשיש רק ביטוי אחד, ה-return אוטומטי

```

- **Parameters** – המשתנים בסוגריים (`a`, `b`): "המצרכים" שהפונקציה מקבלת.
- **Arguments** – הערכים האמיתיים שמעבירים כשקוראים לה: `add(2, 3)`.
- **`return`** – התוצאה שהפונקציה מחזירה. פונקציה בלי `return` מחזירה `undefined`.

## 5. Conditions – תנאים

```typescript if / else if / else
if (age >= 18) {
  console.log('מבוגר');
} else if (age >= 13) {
  console.log('נער');

```

### `===` מול `==` – מלכודת קלאסית

| ביטוי | תוצאה | למה |
|---|---|---|
| `5 === '5'` | `false` | **Strict equality** – בודק גם ערך וגם Type |
| `5 == '5'` | `true` | **Loose equality** – ממיר Types לפני ההשוואה (מסוכן!) |
| `0 == false` | `true` | המרה אוטומטית מפתיעה |
| `null == undefined` | `true` | מקרה מיוחד |

> [!warn] **תמיד** השתמש ב-`===` וב-`!==`. ההמרות האוטומטיות של `==` הן מקור לבאגים שקשה מאוד למצוא.

### Truthy ו-Falsy

ב-`if`, כל ערך נהפך ל-`true` או `false`. הערכים ה-**Falsy** הם: `false`, `0`, `''` (טקסט ריק), `null`, `undefined`, `NaN`. כל השאר **Truthy**. זה שימושי (`if (userName)`), אבל זהירות: גם `0` הוא Falsy, אז `if (count)` לא ייכנס כשהכמות היא 0!

## 7. Scope – איפה משתנה "חי"

**Scope** (טווח) קובע מאיפה אפשר לגשת למשתנה. משתנה שהוגדר עם `const`/`let` בתוך `{ }` קיים **רק בתוך הסוגריים האלה** (זה נקרא **Block scope**). פונקציה רואה משתנים שהוגדרו מחוצה לה, אבל לא להפך.

```typescript Block scope
const shopName = 'החנות';      // נגיש בכל הקובץ
function greet() {
  const greeting = 'שלום';     // קיים רק בתוך greet
  return `${greeting} מ${shopName}`;
}
// console.log(greeting); ← שגיאה: greeting is not defined
```

> [!tip] מה Senior יודע: פונקציות טובות הן **קטנות, עם שם שמתאר פעולה** (`calculateTotal`, לא `doStuff`), ובעדיפות **Pure functions** – מקבלות קלט, מחזירות פלט, ולא משנות שום דבר מחוצה להן. קוד כזה קל לקרוא, קל לבדוק (Testing – מודול 3) וקשה לשבור. ועוד הרגל: **Early return** – לטפל קודם במקרים החריגים ולצאת, במקום לקנן `if` בתוך `if` בתוך `if`.

// מחירים קבועים – const כי הם לא משתנים
const VAT_RATE = 0.17;
const FREE_SHIPPING_FROM = 200;
const SHIPPING_PRICE = 30;

// פונקציה שמחשבת מחיר לפריט אחד
const itemTotal = (price, quantity) => price * quantity;

// פונקציה שמחזירה את עלות המשלוח לפי סכום ההזמנה
function shippingCost(subtotal) {
  if (subtotal === 0) {
    return 0; // Early return – סל ריק, אין משלוח
  }
  if (subtotal >= FREE_SHIPPING_FROM) {
    return 0;
  }
  return SHIPPING_PRICE;
}

// הסל: רשימה של פריטים
const cart = [
  { name: 'מקלדת', price: 150, quantity: 1 },
  { name: 'עכבר', price: 40, quantity: 2 },
];

let subtotal = 0; // let – כי נעדכן אותו בלולאה
for (const item of cart) {
  subtotal += itemTotal(item.price, item.quantity);
}

const shipping = shippingCost(subtotal);
const vat = subtotal * VAT_RATE;
const total = subtotal + vat + shipping;

const isBigOrder = total > 300; // boolean
console.log(`סכום ביניים: ${subtotal} ₪`);
console.log(`משלוח: ${shipping === 0 ? 'חינם!' : shipping + ' ₪'}`);
console.log(`לתשלום: ${total.toFixed(2)} ₪`);

if (isBigOrder) {
  console.log('קיבלת קופון להזמנה הבאה 🎉');
}

## מה קורה בקוד, שלב אחרי שלב

- **קבועים באותיות גדולות** (`VAT_RATE`) – מוסכמה שאומרת "זה ערך קבוע של המערכת". אם המע״מ משתנה, מעדכנים מקום אחד בלבד.
- **`itemTotal`** – Arrow function קצרה: מקבלת שני Parameters ומחזירה את המכפלה. זו **Pure function** – אותו קלט תמיד ייתן אותו פלט.
- **`shippingCost`** – מדגימה **Early return**: בודקים את המקרים המיוחדים קודם ויוצאים מיד. כך אין צורך ב-`else` מקוננים.
- **`cart`** – רשימה (**Array**) של אובייקטים. נלמד אותם לעומק בשיעור הבא; בינתיים מספיק לדעת ש-`item.price` ניגש לשדה `price`.
- **`for...of`** – עוברים על כל פריט בסל ומוסיפים לסכום. `+=` הוא קיצור של `subtotal = subtotal + ...`.
- **`let subtotal`** – המשתנה היחיד שמשתנה, ולכן היחיד שהוא `let`. כל השאר `const`.
- **Ternary operator** – `condition ? a : b` הוא `if/else` קצר שמחזיר ערך: "אם המשלוח 0 – כתוב 'חינם!', אחרת כתוב את המחיר".
- **`toFixed(2)`** – מציג מספר עם שתי ספרות אחרי הנקודה (חשוב לכסף).

## פתרון לדוגמה

```typescript checkPassword.js
const MIN_LENGTH = 8;

function checkPassword(password) {
  // Early return – המקרים הבעייתיים קודם
  if (password.length < MIN_LENGTH) {
    return 'חלשה: לפחות 8 תווים';
  }

  let hasDigit = false;
  let hasUpper = false;
  for (const char of password) {
    if (char >= '0' && char <= '9') {
      hasDigit = true;
    } else if (char !== char.toLowerCase()) {
      hasUpper = true; // אות גדולה באנגלית
    }
  }

  if (hasDigit && hasUpper) {
    return 'חזקה';
  }
  return 'בינונית: הוסף ספרה ואות גדולה';
}

console.log(checkPassword('abc'));        // חלשה
console.log(checkPassword('abcdefgh'));   // בינונית
console.log(checkPassword('Abcdefg1'));   // חזקה
```

**מה למדנו:** `const` לקבוע, `let` לדגלים שמשתנים בלולאה, `for...of` על מחרוזת (עובר תו אחרי תו), `===`/`!==` להשוואה, ו-Early return שמשאיר את הקוד שטוח וקריא.

עד עכשיו עבדנו עם ערכים בודדים. אבל באפליקציה אמיתית יש **רשימות** (כל ההודעות בצ׳אט) ו**ישויות עם הרבה פרטים** (משתמש: שם, אימייל, גיל). בשביל זה יש **Array** ו-**Object**.

- **Object** (אובייקט) = **כרטיס לקוח**: לכל שדה יש שם – "שם", "טלפון", "עיר".

### אנלוגיה שנייה: מסעדה עם זמזם

כשמזמינים בדוכן אוכל, לא עומדים ליד הקופה 10 דקות וחוסמים את כל התור. מקבלים **זמזם** והולכים לשבת. כשהאוכל מוכן – הזמזם רוטט. זה בדיוק **קוד אסינכרוני** (**Async**):

### ארבע המתודות שתשתמש בהן כל יום

| Method | מה עושה | מחזיר |
|---|---|---|
| `map` | הופך כל פריט למשהו אחר | Array חדש **באותו אורך** |
| `filter` | משאיר רק פריטים שעונים לתנאי | Array חדש (קצר או שווה) |
| `find` | מוצא את הפריט **הראשון** שעונה לתנאי | פריט אחד או `undefined` |
| `reduce` | "מקפל" את כל הרשימה לערך אחד (סכום, אובייקט) | ערך אחד |

```typescript map / filter / find / reduce
const prices = [100, 250, 40];
prices.map((p) => p * 1.17);              // [117, 292.5, 46.8]
prices.filter((p) => p > 50);             // [100, 250]
prices.find((p) => p > 200);              // 250
prices.reduce((sum, p) => sum + p, 0);    // 390
```

> [!note] `map` ו-`filter` **לא משנים** את המערך המקורי – הם מחזירים מערך חדש. זה עיקרון חשוב שנקרא **Immutability**, ו-React (מודול 6) מבוסס עליו.

## 4. Async – למה צריך את זה?

JavaScript רצה על **Thread אחד** (חוט ביצוע אחד) – היא עושה **דבר אחד בכל רגע**. אם היא הייתה "מחכה" 2 שניות לתשובה מהשרת, כל הדף היה קופא: אי אפשר ללחוץ, לגלול, כלום. לכן פעולות איטיות רצות "ברקע", ו-JavaScript ממשיכה הלאה.

### האבולוציה: Callback ← Promise ← async/await

```typescript אותו דבר בשלוש תקופות
// 1) Callback – "תתקשר אליי כשתסיים" (מוביל ל-Callback Hell)
getUser(7, (user) => {
  getOrders(user.id, (orders) => {
    console.log(orders);
  });
});

// 2) Promise עם then – שרשרת במקום קינון
getUser(7)
  .then((user) => getOrders(user.id))
  .then((orders) => console.log(orders))
  .catch((err) => console.error(err));

// 3) async/await – נראה כמו קוד רגיל! (זה מה שמשתמשים בו היום)
async function showOrders() {
  try {
    const user = await getUser(7);
    const orders = await getOrders(user.id);
    console.log(orders);
  } catch (err) {
    console.error('משהו נכשל', err);
  }
}
```

- **`async`** לפני פונקציה – הופך אותה לפונקציה שתמיד מחזירה Promise.
- **`await`** – "חכה כאן לתוצאה של ה-Promise", בלי לתקוע את שאר התוכנית.
- **`try/catch`** – אם ה-Promise נכשל (**rejected**), הקוד קופץ ל-`catch`.

### `Promise.all` – לחכות לכמה דברים במקביל

```typescript במקביל במקום בטור
// בטור: 1 שנייה + 1 שנייה = 2 שניות 🐢
const a = await getProducts();
const b = await getCategories();

// במקביל: ~1 שנייה סה״כ 🚀
const [products, categories] = await Promise.all([getProducts(), getCategories()]);
```

> [!warn] אם **אחד** מה-Promises ב-`Promise.all` נכשל – כל ה-`Promise.all` נכשל. כשרוצים לקבל את כל התוצאות גם אם חלק נכשלו, משתמשים ב-`Promise.allSettled`.

## 5. Event Loop – איך זה עובד מאחורי הקלעים

| חלק | תפקיד | באנלוגיית המסעדה |
|---|---|---|
| **Call Stack** | הקוד שרץ **עכשיו**, פונקציה בתוך פונקציה | הטבח היחיד שעובד על מנה אחת |
| **Web APIs / Node APIs** | מטפלים בפעולות איטיות ברקע (רשת, טיימרים, קבצים) | הספקים והתנור – עובדים לבד |
| **Queue** (תור) | פונקציות שמוכנות לרוץ כשה-Stack יתפנה | ערימת הזמזמים שמוכנים |
| **Event Loop** | בודק כל הזמן: "ה-Stack ריק? אז תכניס את הבא מהתור" | המנהל שמעביר מנה מוכנה לטבח |

```typescript מה יודפס קודם?
console.log('1');
setTimeout(() => console.log('2'), 0);
console.log('3');
```

## 4. Discriminated Unions – הכלי החזק ביותר

```typescript Discriminated union + exhaustive check
type Notification =

  switch (n.kind) {
    case 'email':
      return `מייל ל-${n.to}`;     // כאן TS יודעת ש-n הוא email
    case 'sms':
      return `SMS ל-${n.phone}`;
    case 'push':
      return `Push למכשיר ${n.deviceId}`;
    default: {
      const never: never = n;      // Exhaustive check
      return never;
    }
  }
}
```

**Exhaustive check:** אם מחר מישהו יוסיף `{ kind: 'whatsapp' }` ל-Union ושכח לטפל בו – השורה עם `never` תיתן **שגיאת קומפילציה**. ה-Compiler מכריח אותך לטפל בכל מקרה.

const PaymentSchema = z.discriminatedUnion('method', [

  z.object({ method: z.literal('wallet'), amount: z.number().positive(), walletId: z.string() }),

  return { ok: true, value: parsed.data };

## מה קורה בקוד?

- **`z.discriminatedUnion('method', [...])`** – Schema של Zod שאומר: "המידע הוא אחת משלוש צורות, ושדה `method` מבדיל ביניהן". כל צורה מגדירה בדיוק אילו שדות חובה ואילו כללים חלים עליהם (`positive()`, `length(4)`).
- **`z.literal('card')`** – הערך חייב להיות בדיוק המחרוזת `'card'` – Literal type בזמן ריצה.
- **`z.infer<typeof PaymentSchema>`** – כאן הקסם: לא כותבים את ה-Type פעמיים. ה-Type `Payment` **נגזר** מה-Schema, אז אי אפשר שהבדיקה וה-Type "יתרחקו" זה מזה.
- **`Result<T>`** – Generic: "תוצאה של משהו". `Result<Payment>` היא הצלחה עם `Payment` או כישלון עם `error`. זה גם Discriminated union – לפי השדה `ok`.
- **`input: unknown`** – הפונקציה מודה: "אני לא יודעת מה קיבלתי". TypeScript לא תיתן לגשת לשדות עד שנבדוק.
- **`safeParse`** – לא זורק שגיאה, אלא מחזיר `{ success, data }` או `{ success, error }`. יש גם `parse` שזורק – שימושי כשרוצים שהשגיאה "תעוף" ל-Middleware של שגיאות (מודול 4).
- **`switch (p.method)`** – בתוך כל `case`, TypeScript **מצמצמת** (**Narrowing**) את ה-Type: ב-`'card'` אפשר לגשת ל-`last4`, אבל לא ל-`iban`.
- **`const unreachable: never = p`** – Exhaustive check. אם תוסיף `'crypto'` ל-Schema ולא תוסיף `case`, הקוד לא יתקמפל.
- **`if (result.ok)`** – Narrowing לפי `ok`: בתוך ה-`if` יש `value`, ב-`else` יש `error`.

> [!tip] התבנית הזו – Schema בגבול המערכת, Type נגזר, Discriminated union ו-Exhaustive check – היא בדיוק מה שתראה בקוד Backend רציני. תפגוש אותה שוב בבניית API (מודול 4) ובטיפול ב-Events (מודול 8).
