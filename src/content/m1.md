## מה זה בכלל "האינטרנט"?

האינטרנט הוא פשוט **הרבה מחשבים שמחוברים זה לזה ומדברים בשפה מוסכמת**. כשאתה פותח אתר, המחשב שלך (או הטלפון) שולח **בקשה** למחשב אחר, איפשהו בעולם, ומקבל ממנו **תשובה**.

### אנלוגיה: מסעדה

- **אתה** יושב ליד השולחן ← זה ה-**Client** (לקוח) – הדפדפן שלך.
- **המטבח** מכין את האוכל ← זה ה-**Server** (שרת) – מחשב שמחכה לבקשות.
- **המלצר** מעביר הזמנות ומנות ← זה ה-**Network** (הרשת, האינטרנט).
- **התפריט** קובע מה מותר להזמין ואיך ← זה ה-**Protocol** – במקרה שלנו **HTTP**.

אתה לא נכנס למטבח ולא יודע איך מבשלים. אתה רק שולח הזמנה מסודרת (**Request**) ומקבל מנה (**Response**). ככה בדיוק עובד אתר.

> [!tip] כמעט כל מה שתבנה כמפתח Full Stack הוא אחד משני הצדדים: **Frontend** (צד לקוח – מה שהמשתמש רואה) או **Backend** (צד שרת – הלוגיקה והנתונים). מפתח Full Stack יודע לבנות את שניהם ולחבר ביניהם.

### למה זה חשוב לך?

כל באג, כל בעיית ביצועים וכל שאלה בראיון עבודה מתחילים בשאלה: "מה בדיוק קורה בין הדפדפן לשרת?". מי שמבין את המסלול הזה יודע לחפש בעיות במקום הנכון.

## מה קורה כשמקלידים כתובת בדפדפן?

נניח שהקלדת `https://shop.example.com/products` ולחצת Enter. הנה המסע, צעד אחר צעד:

1. **פירוק ה-URL.** הדפדפן מבין שיש כאן שלושה חלקים: הפרוטוקול `https`, שם השרת `shop.example.com`, והנתיב `/products` (איזה "דף" אנחנו רוצים).
2. **DNS – ספר הטלפונים של האינטרנט.** מחשבים לא מכירים שמות, רק מספרים שנקראים **IP Address** (למשל `93.184.216.34`). הדפדפן שואל שרת DNS: "מה המספר של shop.example.com?" ומקבל כתובת IP.
3. **TCP Connection.** הדפדפן "מתקשר" לשרת בכתובת הזאת, כמו חיוג בטלפון. בשלב הזה שני הצדדים מסכימים לדבר.
4. **TLS (הצפנה).** בגלל ה-`s` ב-`https`, הצדדים מחליפים מפתחות הצפנה. מעכשיו אף אחד באמצע (למשל ברשת WiFi ציבורית) לא יכול לקרוא את התוכן.
5. **HTTP Request.** הדפדפן שולח הודעת טקסט מסודרת: "תביא לי בבקשה את `/products`".
6. **ה-Server עובד.** קוד ב-Backend מקבל את הבקשה, אולי שולף מוצרים ממסד נתונים, ובונה תשובה.
7. **HTTP Response.** השרת מחזיר **Status Code** (למשל `200` = הצלחה) ואת התוכן – HTML של דף, או נתונים בפורמט JSON.
8. **Rendering – הדפדפן מציג.** אם קיבל HTML, הוא בונה את הדף, מוריד קבצי CSS, JavaScript ותמונות (כל אחד מהם הוא בקשה נוספת!) ומציג לך את התוצאה.

> [!note] כל השלבים האלה קורים בדרך כלל בפחות משנייה. כשאתר "איטי", אחד מהשלבים האלה הוא צוואר הבקבוק – ותפקיד המפתח למצוא איזה.

### מונחים בסיסיים שחייבים להכיר

| מונח | מה זה בשפה פשוטה |
|---|---|
| **Client** (לקוח) | התוכנה ששולחת בקשות – בדרך כלל דפדפן או אפליקציה |
| **Server** (שרת) | מחשב (או תוכנה) שמחכה לבקשות ומחזיר תשובות |
| **IP** | "מספר הטלפון" של מחשב ברשת |
| **DNS** | שירות שמתרגם שם (google.com) לכתובת IP |
| **Port** (פורט) | "שלוחה" בתוך המחשב – 443 ל-HTTPS, 80 ל-HTTP, 5173 לשרת הפיתוח שלנו |
| **localhost** | שם מיוחד שאומר "המחשב שלי". `localhost:5173` = שלוחה 5173 במחשב שלך |

### Frontend מול Backend

- **Frontend** (צד לקוח): HTML (מבנה), CSS (עיצוב), JavaScript (התנהגות). רץ **בתוך הדפדפן** של המשתמש. בפרויקטים מודרניים כותבים אותו עם **React**.
- **Backend** (צד שרת): קוד שרץ **על השרת**. מקבל בקשות, בודק הרשאות, קורא וכותב למסד נתונים. אצלנו: **Node.js + TypeScript**.
- **Database** (מסד נתונים): המקום שבו המידע נשמר לאורך זמן. אצלנו: **PostgreSQL**.

> [!warn] טעות נפוצה של מתחילים: לשים סודות (סיסמאות, מפתחות API) בקוד ה-Frontend. כל מה שנשלח לדפדפן – **כל אחד יכול לראות**. סודות נשארים תמיד בצד השרת.

## מה רואים כשמריצים את הפקודות?

- **`nslookup`** מראה את שלב ה-DNS: אתה שולח שם ומקבל `Address: 93.184.215.14` (או דומה). זה בדיוק מה שהדפדפן עושה מאחורי הקלעים.
- **`curl -v`** הוא "דפדפן בלי מסך". השורות שמתחילות ב-`>` הן **הבקשה** שיצאה מהמחשב שלך, והשורות שמתחילות ב-`<` הן **התשובה** מהשרת. תראה שם בין היתר:
  - `> GET / HTTP/2` – "תביא לי את הדף הראשי".
  - `< HTTP/2 200` – "בבקשה, הצליח".
  - `< content-type: text/html` – "מה שאני שולח לך הוא דף HTML".
- **`curl -I`** מבקש רק את הכותרות (Headers) – שימושי לבדוק מהר אם שרת חי.

## HTTP – השפה שבה הדפדפן והשרת מדברים

**HTTP** (HyperText Transfer Protocol) הוא סט כללים שקובע **איך נראה Request ואיך נראה Response**. זה כמו טופס בבנק: יש שדות קבועים (שם, מספר חשבון, סכום), וכל פקידה בכל סניף יודעת לקרוא אותו.

כל שיחה ב-HTTP היא **זוג**: Request אחד ← Response אחד. השרת לא "זוכר" אותך בין בקשה לבקשה (זה נקרא **Stateless**). לכן, כשאתה מחובר לאתר, הדפדפן שולח בכל בקשה "תעודה מזהה" (Cookie או Token).

> [!tip] כמפתח Backend רוב היום שלך הוא לבנות **Endpoints** (נקודות קצה) – כתובות שמקבלות בקשות HTTP ומחזירות תשובות. אם תבין HTTP היטב, תבין את רוב העבודה.

## המבנה של בקשה

```text בקשת HTTP אמיתית (מה שנשלח ברשת)
POST /api/orders HTTP/1.1
Host: shop.example.com
Content-Type: application/json
Authorization: Bearer eyJhbGciOi...

{"productId": 42, "quantity": 2}
```

- **Method:** מה אני רוצה לעשות – `POST` = ליצור משהו חדש.
- **Path:** על מה – `/api/orders`.
- **Headers:** מידע נוסף על הבקשה – מה הפורמט, מי אני.
- **Body:** התוכן עצמו – כאן, הזמנה בפורמט JSON.

### ה-Methods העיקריים

| Method | משמעות | דוגמה |
|---|---|---|
| `GET` | **קריאה** – תביא לי מידע. לא משנה כלום | `GET /api/products` |
| `POST` | **יצירה** – צור משהו חדש | `POST /api/orders` |
| `PUT` | **החלפה** – החלף את כל הרשומה | `PUT /api/users/7` |
| `PATCH` | **עדכון חלקי** – שנה רק שדה אחד | `PATCH /api/users/7` |
| `DELETE` | **מחיקה** | `DELETE /api/orders/15` |

### Status Codes – "איך הלך?"

ה-**Status Code** הוא מספר בן 3 ספרות. הספרה הראשונה אומרת הכל:

| טווח | משמעות | הקודים שחייבים לזכור |
|---|---|---|
| **2xx** | הצלחה | `200` OK · `201` נוצר · `204` הצליח, אין תוכן |
| **3xx** | הפניה למקום אחר | `301` עבר דירה לתמיד · `304` לא השתנה (תשתמש במה ששמור אצלך) |
| **4xx** | **אתה** (הלקוח) טעית | `400` בקשה שגויה · `401` לא מזוהה · `403` אין הרשאה · `404` לא נמצא · `409` התנגשות · `422` הנתונים לא תקינים · `429` יותר מדי בקשות |
| **5xx** | **השרת** נכשל | `500` שגיאה פנימית · `502`/`503` השרת לא זמין · `504` תם הזמן |

> [!tip] כלל אצבע לראיונות: **4xx = הבעיה אצל מי ששלח, 5xx = הבעיה אצלנו**. זה גם משפיע על התגובה: בקשה שקיבלה 4xx לא כדאי לשלוח שוב כמו שהיא; בקשה שקיבלה 503 אפשר לנסות שוב בעוד רגע.

### JSON – פורמט הנתונים של הרשת

**JSON** (JavaScript Object Notation) הוא טקסט שמייצג נתונים מסודרים. כמעט כל API מודרני מדבר JSON:

```json הזמנה בפורמט JSON
{
  "id": 1543,
  "customer": "אורי",
  "paid": true,
  "total": 249.9,
  "items": [
    { "productId": 42, "name": "מקלדת", "quantity": 2 }
  ]
}
```

כללים: מפתחות תמיד במירכאות כפולות, ערכים יכולים להיות טקסט, מספר, `true`/`false`, `null`, רשימה `[]` או אובייקט `{}`.

### Headers שתפגוש כל יום

- `Content-Type` – מה הפורמט של הגוף (`application/json`).
- `Authorization` – "התעודה המזהה" (למשל `Bearer <token>`).
- `Cookie` / `Set-Cookie` – הדרך של השרת "לזכור" אותך בין בקשות.
- `Cache-Control` – כמה זמן מותר לשמור את התשובה בזיכרון מטמון.

> [!warn] **CORS** – אם אתר A מנסה לקרוא בקשה לשרת B, הדפדפן חוסם את זה אלא אם השרת B מאשר במפורש (בכותרת `Access-Control-Allow-Origin`). זו אחת השגיאות הראשונות שכל מפתח Full Stack נתקל בה – וזה **לא באג**, זו הגנה.

## הסבר שורה אחרי שורה

- **`fetch(url)`** – הפונקציה המובנית בדפדפן (וב-Node.js) לשליחת בקשות HTTP. ברירת המחדל היא `GET`.
- **`await`** – בקשה ברשת לוקחת זמן. `await` אומר "חכה כאן עד שהתשובה תגיע" בלי לתקוע את כל הדף (נלמד את זה לעומק במודול 2).

- **`response.json()`** – הגוף מגיע כטקסט; הפונקציה הזו ממירה אותו לאובייקט שאפשר לעבוד איתו.
- **`JSON.stringify(...)`** – הכיוון ההפוך: אובייקט JavaScript ← טקסט JSON לשליחה.
- **`headers`** – אנחנו מצהירים מה אנחנו שולחים (`Content-Type`) ומי אנחנו (`Authorization`).

## איך דף אינטרנט נבנה?

כל דף אינטרנט מורכב משלוש שפות שעובדות יחד. **אנלוגיה: בית.**

- **HTML** = **הקירות והחדרים**. המבנה: כותרת, פסקה, כפתור, טופס.
- **CSS** = **הצבע, הריהוט והעיצוב**. איך הכל נראה: צבעים, גדלים, מיקום.
- **JavaScript** = **החשמל והאינסטלציה**. מה קורה כשלוחצים: פתיחת תפריט, שליחת טופס, עדכון מידע בלי לרענן.

כש-React (שנלמד במודול 6) "מצייר" מסך, הוא בסוף מייצר HTML ו-CSS ומשתמש ב-JavaScript – אז ההבנה הבסיסית הזו היא היסוד של כל Frontend.

## מ-HTML לדף על המסך

### 1. HTML – תגיות

HTML בנוי מ-**Tags** (תגיות). לכל תגית יש פתיחה וסגירה, ואפשר לשים תגיות בתוך תגיות:

```html דף HTML מינימלי
<!doctype html>
<html lang="he" dir="rtl">
  <head>
    <title>החנות של אורי</title>
    <link rel="stylesheet" href="style.css" />
  </head>
  <body>
    <h1>ברוכים הבאים</h1>
    <p id="greeting">שלום, אורח</p>
    <button id="login">התחבר</button>
    <script src="app.js"></script>
  </body>
</html>
```

- `<head>` – מידע **על** הדף (כותרת הלשונית, קבצי עיצוב).
- `<body>` – מה שהמשתמש **רואה**.
- `id` – שם ייחודי לאלמנט, כדי ש-CSS ו-JavaScript ימצאו אותו.
- `dir="rtl"` – כיוון מימין לשמאל, חובה לאתרים בעברית.

### 2. ה-DOM – הדף כ-Tree

הדפדפן קורא את ה-HTML ובונה ממנו **Tree** (עץ) של אובייקטים שנקרא **DOM** (Document Object Model). כל תגית היא "ענף". JavaScript לא עובד ישירות עם הטקסט של ה-HTML – הוא עובד עם העץ הזה: מוצא ענף, משנה אותו, והדפדפן מצייר מחדש.

### 3. CSS – Selectors ו-Rules

```css עיצוב בסיסי

button {
  background: #6d4aff;
  color: white;
  padding: 8px 16px;
  border-radius: 8px;
}

/* בוחר לפי id */

  font-size: 20px;
```

היום רוב הצוותים משתמשים ב-**Tailwind CSS** – במקום לכתוב קובץ CSS נפרד, כותבים "מחלקות" קטנות ישירות ב-HTML, כמו `class="bg-violet-600 text-white p-2 rounded-lg"`. האתר הזה בנוי ככה.

### 4. JavaScript – Events ושינויים

JavaScript **מאזין ל-Events** (לחיצה, הקלדה, טעינה) ו**משנה את ה-DOM** בתגובה. זה מה שהופך דף סטטי לאפליקציה.

### 5. DevTools – הכלי הכי חשוב שלך

> [!tip] הרגל של מקצוענים: כשמשהו לא עובד באתר, הדבר הראשון הוא לפתוח **Console** (יש שגיאה אדומה?) ו-**Network** (יש בקשה שנכשלה?). 80% מהבאגים מתגלים ככה.

## מה קורה כאן?

1. **`document.getElementById`** – מחפש בעץ ה-DOM אלמנט עם `id` מסוים ומחזיר אותו.
2. **`addEventListener('click', ...)`** – "כשילחצו על הכפתור, תריץ את הפונקציה הזו". הפונקציה לא רצה עכשיו – היא רצה **רק כשהאירוע קורה**.
3. **`button.disabled = true`** – פרט קטן שמראה מקצועיות: בזמן שמחכים לשרת, לא נותנים ללחוץ שוב (אחרת יישלחו שתי בקשות).
4. **`try / catch`** – אם משהו נכשל (אין רשת, השרת החזיר שגיאה), אנחנו לא "קורסים" אלא מציגים הודעה ידידותית ומחזירים את הכפתור למצב פעיל.
5. **`greeting.textContent = ...`** – משנים את הטקסט בעץ, והדפדפן מעדכן את המסך מיד.

> [!note] React (מודול 6) עושה את כל זה בצורה הרבה יותר נוחה: במקום לחפש אלמנטים ולשנות אותם ידנית, אתה מתאר **איך המסך צריך להיראות** לפי המידע, ו-React דואג לעדכן את ה-DOM בעצמו.

```typescript app.js
const countEl = document.getElementById('count');
let count = Number(localStorage.getItem('count') ?? 0); // טעינה מהזיכרון
countEl.textContent = String(count);

function render() {
  countEl.textContent = String(count);
  countEl.style.color = count >= 10 ? 'green' : 'black';
  localStorage.setItem('count', String(count)); // שמירה בדפדפן
}

document.getElementById('plus').addEventListener('click', () => {
  count += 1;
  render();
});

document.getElementById('reset').addEventListener('click', () => {
  count = 0;
  render();
});
```

**מה למדנו מזה:** **State** – המשתנה `count`; פונקציית **render** שמעדכנת את המסך לפי המצב; ושמירה ב-`localStorage` כדי שהמידע ישרוד רענון. זה בדיוק הרעיון ש-React בנוי עליו.
